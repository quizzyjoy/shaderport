# 设计说明（design）

> 状态：v0.1 已实现（48 个效果）· 最后更新 2026-10-20
>
> 本文保留立项时的背景与取舍；实现结果与验收数据见 `README.md`、`docs/device-matrix.md`
> 与 `docs/roadmap-1.0.md`。

## 1. 问题

现代着色器效果生态正在向 **WebGPU/WGSL** 收敛（如 `shaders` 这类库提供 200+ 效果），但**真实设备的可用面**要窄得多：

- HarmonyOS **ArkWeb**（Chrome 144 内核）实测：`navigator.gpu` 存在，**`requestAdapter()` 返回 null** → WebGPU 效果完全不可用；
- 大量旧 Android WebView、部分桌面浏览器同理；
- 原生侧（HarmonyOS/Android/iOS App）**根本没有 WebGPU**，只有 **OpenGL ES / Metal / Vulkan**。

结果是：**同一套效果无法跨"现代 Web / 旧 Web / 原生"三端复用**，每个团队都要重写。

## 2. 目标

1. **可转换**：WGSL → GLSL ES 3.00 的可靠转换路径（含能力缺口报告，而不是静默产出跑不起来的代码）。
2. **可复用**：一批可跑在 GLES 3.0 的效果，附**规格**（uniform、成本档、驱动要求）与**参考图**，让"观感"可验收而非靠感觉。
3. **可落地**：native（C++/GLES）与 Web（WebGL2）两侧的集成示例。
4. **可自检**：目标机型能力探测（GL 版本、扩展、浮点渲染目标、最大纹理/UBO），决定哪些效果可用、哪些要降级。

## 3. 非目标

- 不做渲染引擎、不做场景图、不做 UI 框架；
- 不实现 WebGPU 运行时（上游 TypeGPU/`shaders` 的职责）；
- 不追求效果数量，追求"每个效果都在目标机型上跑得住、看得对"。

## 4. 关键设计决定

| 决定 | 理由 |
|---|---|
| **以 GLSL ES 3.00 为一等目标**（而非 ES 1.00/2.00） | `#version 300 es` 是当前设备事实标准（HarmonyOS/中端 Android 均支持），且支持 `gl_VertexID`、UBO、纹理数组等；ES 1.00 会失去太多表达力 |
| **转换用 `naga`（WGSL → GLSL ES 300/310）** | 官方文档明确列出 ES 300/310 后端；避免自研编译器；Tint/SPIRV-Cross 作为交叉验证 |
| **效果以"规格 + 源码 + 参考图"三件套交付** | 效果的价值一半是观感，没有参考图就无法验收；规格让跨端参数一致 |
| **明确"无 compute"约束** | GLES 3.0 **没有 compute shader**（需 ES 3.10）；基于 compute 的效果必须改写为 VS/FS + FBO 多趟，或在规格中标记为不支持 |
| **效果按用途分层（背景 / 主视效）** | 两者的成本预算、对比度、干扰度要求完全不同；混在一起会导致"背景抢戏"或"主视效不够猛" |
| **许可 Apache-2.0** | OpenHarmony 生态推荐；与专利授权条款更明确；便于被商业项目采用 |

## 5. 架构（已实现）

```
┌────────────────────┐     ┌──────────────────────┐     ┌───────────────────┐
│  效果定义（规格）    │ ──▶ │ tools/wgsl2glsles    │ ──▶ │ effects/<name>/   │
│  uniform / 成本 / 层 │     │ naga 后端 + 能力检查   │     │ passes/*.glsl + spec.json │
└────────────────────┘     └──────────────────────┘     └───────────────────┘
                                     │                            │
                                     ▼                            ▼
                          ┌────────────────────┐        ┌──────────────────┐
                          │ 能力报告（缺口清单） │        │ 集成示例         │
                          │ compute/浮点FBO/…   │        │ C++/GLES·WebGL2  │
                          └────────────────────┘        └──────────────────┘
```

## 6. 与上游项目的关系

- 上游 [`shader-effects-inc/shaders`](https://github.com/shader-effects-inc/shaders)（MIT）是 **WebGPU 效果库**。本项目从 v4.0.4 转译了 **48 个效果资产**（`ported`，逐条溯源见 `spec.json` 的 `provenance` 与 `THIRD_PARTY_NOTICES.md`），但**不包含其运行时**（TypeGPU、框架绑定、CLI、遥测），也不包含未被移植的效果源码；渲染管线、参数元数据与示例工程均为本项目实现。
- `naga` 提供转换能力；`@typegpu/gl` 证明 WebGL 侧路径可行。
- 首个真实使用者是一个原生 GLES 音乐可视化 App（分层：背景 → 主视效 → 歌词/播控），本项目从中沉淀可复用部分。

## 7. 决策与遗留

立项时的四个未决问题，现状如下：

| # | 问题 | 结论 |
|---|---|---|
| 1 | 规格用 `spec.md` 还是 `spec.json` + 生成文档 | **已决**：`spec.json` 为唯一源（含 `resolved` 默认值与 `validation`）；`spec.md` 仅作可选的人类可读视图，v0.1 不提交 |
| 2 | 是否提供参考图自动比对 | **已实现**：`tools/render-reference` 支持抓帧、`--strict` 与逐像素 diff；模拟器 48/48 通过 |
| 3 | 能力报告的输出格式 | **遗留**：`capability-probe` 未实现，顺延到 1.x；当前以设备矩阵与运行时错误反馈代替 |
| 4 | 是否提供 GLSL ES 1.00 降级 | **已决**：不提供，只支持 ES 3.00；理由见 §4 |
